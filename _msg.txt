Detect the container with proot-distro itself, and fix its install syntax

Re-running the build failed with:

    Error: container 'botapi' already exists. Specify a different name with '--name NAME'.

The container was fine; the script could not see it. proot-distro 5.x keeps the rootfs at

    $PROOT_BASE/containers/<name>/rootfs

while the script only looked at the 4.x location,

    $PROOT_BASE/installed-rootfs/<name>

So the -d test failed, the script decided to install again, and proot-distro refused because the
container it was about to create already existed. Measured on the device: 658 MB under
containers/botapi/rootfs, with manifest.json beside it, and `proot-distro list` naming botapi.

Three changes:

  - both layouts are checked, so either version works, and PROOT_BASE can be overridden if a
    later release moves it again
  - the decision now asks `proot-distro list` first, which is authoritative and does not depend
    on any path; the path test remains only as a fallback
  - `install --name=NAME debian:stable` - 5.x documents the name as an option and the argument
    slot as the image reference: `install [OPTIONS] (IMAGE:TAG or URL or FILE)`. The tag is
    explicit so a future `latest` cannot silently change the base.
