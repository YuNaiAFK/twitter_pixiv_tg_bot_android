Pass the proxy into the Debian chroot, which does not inherit Termux's

The server build runs pt-get update and git clone github.com inside a proot Debian rootfs,
and neither step had a proxy. A chroot has its own apt: Termux's apt.conf.d/95proxy lives inside
$PREFIX and means nothing to a Debian rootfs. apt also ignores the *_proxy environment
variables for its own transport, so exporting them in Termux was never going to be enough.

Without this the build fails immediately in mainland China, with the same misleading symptom as
before - "does not have a Release file", naming a repository that is working fine.

The HTTP form is required and is enforced: apt rejects SOCKS outright with "Unsupported proxy
configured" and reports it as a broken repository. When ~/.proxy-url is not an http:// URL it is
discarded with a warning, so a failure stays honest instead of looking like a network outage.

The value travels in Termux's own $PREFIX/tmp, because --shared-tmp is what binds that
directory to /tmp inside the chroot - writing to ~/ or to / would leave the chroot without it.
Inside the chroot the script writes /etc/apt/apt.conf.d/95proxy and sets git's proxy with
--system, since there is no matching user in the rootfs.
