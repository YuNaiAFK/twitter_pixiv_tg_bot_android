Fix the dpkg prompt that hung every install attempt

The root cause of four failed installs, found by screenshotting the phone: dpkg stops at the
OpenSSL configuration-file conflict and waits for a keyboard that is not there.

    Setting up openssl (1:3.6.5) ...
    Configuration file '/data/data/com.termux/files/usr/etc/tls/openssl.cnf'
    *** openssl.cnf (Y/I/N/O/D/Z) [default=N] ?

DEBIAN_FRONTEND=noninteractive does NOT suppress that prompt, and the previous version threw
the output away with >/dev/null 2>&1, so it looked like a hang rather than a question.
Verified on the device: with the same flags plus </dev/null, 'dpkg --configure -a' exits 0 in
seconds. Reading EOF is what makes dpkg take its default; the flags alone do not.

Every command that can prompt now reads stdin from /dev/null - dpkg, apt-get update,
apt-get install, pip, git clone and git pull. A question can no longer block anything.

Also corrected two of my own misdiagnoses:

  - 'dpkg -l | grep -c ^i[^i]' reported zero packages installed, which looked like a broken
    database. It is the wrong format: dpkg's status file uses the multi-line
    'Status: install ok installed'. The device actually had 75 packages, all correctly
    configured.
  - 'dpkg --configure -a' was never slow. It was waiting on the prompt.

The proxy is now detected and used first, since it measured 200 as both SOCKS5 and HTTP on
10808, and mirror switching only happens when there is no proxy.
