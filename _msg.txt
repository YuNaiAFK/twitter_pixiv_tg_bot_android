Use the HTTP proxy form for apt and pip, which cannot speak SOCKS

    $ apt-get update
    Unsupported proxy configured: socks5://127.0.0.1:10808
    E: The repository 'https://packages-cf.termux.dev/apt/termux-main stable Release'
       does not have a Release file.

The message names the REPOSITORY, so this reads as a broken mirror. I chased that: every Termux
mirror serves its Release file correctly - all five answering 200 with identical 13134-byte
content from a PC on the same network - while apt failed on every one of them. The SOCKS line
above the error is the only real clue.

pip has the same limitation for a different reason and says so differently:

    ERROR: Could not install packages due to an OSError: Missing dependencies for SOCKS support.

It needs PySocks to speak SOCKS, and installing PySocks needs pip. Neither tool hints that the
HTTP form is the answer.

Three places held the SOCKS value and only the third mattered:

  .bashrc              read from ~/.proxy-url, so it was only a carrier
  ~/.proxy-url         already HTTP by the time this was found
  apt.conf.d/95proxy   **the actual cause** - apt reads this file for its own transport and it
                       outranks the environment, so a terminal-only fix changed nothing

The bootstrap now writes the HTTP form to apt.conf.d, to ~/.proxy-url and to git; the SOCKS form
goes to ~/.proxy-url-socks for tools that prefer it. SAVED_URL is \, so
a SOCKS URL can no longer reach apt at all.
