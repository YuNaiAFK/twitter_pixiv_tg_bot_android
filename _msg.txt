Fix cookie paths on Android, and the SOCKS proxy that broke pip

Two failures from the first successful start on the phone.

1. Cookie paths resolved from the wrong directory, silently. BASE_DIR is bot.py's own
   directory, so a relative cookies/twitter.txt became
   .../twitter_pixiv_tg_bot/bot/cookies/twitter.txt - while the installer and the README put
   the cookies beside .env at the project root. The bot logged "Cookie 檔不存在，已略過",
   reported X/Twitter 未設定 and e-hentai 未設定（只能讀取公開畫廊）, and carried on. That is
   the worst shape of bug: a bot that looks like it works with two of its three features
   quietly disabled.

   resolve_relative_path() now checks the project root before BASE_DIR, and both
   resolve_cookie_file() and resolve_ehentai_cookies() use it. Verified against a simulated
   layout containing a file in each place; the Windows tree is unaffected because its cookies/
   is also at the project root.

2. pip cannot use a SOCKS proxy. http_proxy=socks5://... made every install fail with
   "Could not install packages due to an OSError: Missing dependencies for SOCKS support" -
   pip needs PySocks, and installing PySocks needs pip. Measured: v2rayNG's port answers both
   protocols, so the bootstrap now records the SOCKS form for apt/curl/git and the HTTP form
   for pip, falling back to a direct connection when there is no HTTP listener.

Also replaced the install check. It piped pip through 	ail and tested the pipeline's exit
status, which is tail's and always 0, so a complete failure was reported as success - the
packages were in fact never installed, and only the bot failing to start revealed it. The check
now imports all five modules and fails loudly.
