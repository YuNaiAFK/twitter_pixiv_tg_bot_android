Initialise the td submodule, without which CMake cannot configure

The first chroot build reached CMake and failed with:

    CMake Error at CMakeLists.txt:22 (prevent_in_source_build):
      Unknown CMake command "prevent_in_source_build".

That message points at the wrong thing. The top-level CMakeLists.txt does:

    add_subdirectory(td EXCLUDE_FROM_ALL)                          # line 5
    set(CMAKE_MODULE_PATH "${CMAKE_CURRENT_SOURCE_DIR}/td/CMake")  # line 10
    include(PreventInSourceBuild)                                  # line 21
    prevent_in_source_build()                                      # line 22

`td` is a git submodule. `git clone --depth 1` does not fetch submodules, and `--recursive` is
not implied by `--depth 1`, so td/ was empty and td/CMake/PreventInSourceBuild.cmake did not
exist. `include()` of a missing module is not fatal in CMake, so the configure carried on and
the failure surfaced one line later as an unknown command - which reads like a broken upstream
CMakeLists or a missing CMake package, and is neither.

Added `git submodule update --init --recursive` after the clone, plus an explicit check that
td/CMake/PreventInSourceBuild.cmake exists afterwards, so if the submodule fetch itself fails
the error names that instead of blaming CMake.

The Debian rootfs install before this step worked: 706 MB of aarch64 rootfs with g++, git and
perl in place, so only the source checkout was wrong.
