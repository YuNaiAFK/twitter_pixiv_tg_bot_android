Pass trust_env through httpx_kwargs, which is what HTTPXRequest accepts

The previous commit set request_kwargs["trust_env"] = False directly on HTTPXRequest. That
keyword does not exist and the bot died at startup on the phone:

    File ".../bot/bot.py", line 8121, in build_application
        HTTPXRequest(**request_kwargs)
    TypeError: HTTPXRequest.__init__() got an unexpected keyword argument 'trust_env'

Its real signature ends with `proxy` and `httpx_kwargs`, and it builds its client with
`httpx.AsyncClient(**self._client_kwargs)`. So httpx_kwargs is where trust_env belongs:

    HTTPXRequest(..., httpx_kwargs={"trust_env": False})

Verified: the object constructs, and `_client_kwargs["trust_env"]` is False, so the value really
does reach httpx rather than being swallowed.

A check now builds a real HTTPXRequest with the same arguments build_application uses and asserts
that trust_env arrived at the client, so this cannot regress into a startup crash again.

The NO_PROXY half of the change was already correct and is unchanged: httpx honours it under
trust_env, which is why it covers gallery-dl and the bot's own outbound calls as well.
