Keep local Bot API traffic off the VPN

With a self-hosted server on 127.0.0.1:8081, every Bot API call was being tunnelled out to the
VPN and back. python-telegram-bot's HTTPXRequest defaults to trust_env=True, so httpx reads
HTTP_PROXY / HTTPS_PROXY / ALL_PROXY from the environment - and on the phone those are set in
~/.bashrc so gallery-dl can reach Twitter, Pixiv and e-hentai.

Measured: /proc/net/tcp showed the established socket to 127.0.0.1:8081 owned by the VPN's uid
(10201) rather than the bot's (10209). It works, but it adds a round trip through the tunnel to
every getUpdates and every upload, and it would break outright on a VPN configured to bypass
local addresses.

Two changes:

  - telegram_base_is_local() decides whether the base URL is loopback, and PTB's HTTPXRequest
    gets trust_env=False when it is. Only loopback: a *remote* self-hosted server is a normal
    case and must keep using the proxy.
  - bypass_proxy_for_loopback() adds 127.0.0.1, localhost and ::1 to NO_PROXY at startup. That
    covers the bot's own client and every subprocess too, since requests and aiohttp honour it -
    existing entries are preserved rather than overwritten.

Three checks added, including one for the case where a user already has a NO_PROXY list.

While writing those: the first version of the test failed against correct code, because Windows'
os.environ is case-insensitive and popping "no_proxy" also removed the "NO_PROXY" it had just
set. The test now says so, so the next person does not chase the same ghost.
