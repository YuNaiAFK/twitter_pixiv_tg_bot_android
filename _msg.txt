Document the server deployment, and add a boot script for both services

Records what the build actually required, all of it found by measurement on a OnePlus 8 Pro:

  - proot-distro 5.x moved the rootfs to containers/<name>/rootfs, and the binary cannot be run
    directly because its interpreter is Debian's /lib/ld-linux-aarch64.so.1
  - `--dir` needs the directory to exist and takes a chroot path, not a Termux one
  - the loopback IS shared, and every contrary conclusion came from testing via `su 10209`,
    whose u:r:magisk:s0 domain cannot create sockets
  - proot needs no root, and `su` breaks the build by changing the domain
  - the chroot has its own apt and does not inherit Termux's proxy; apt rejects SOCKS and
    reports it as a missing Release file
  - PKG_CONFIG_PATH must be scrubbed or pkg-config answers with Termux's OpenSSL and the build
    compiles bionic headers with Debian's gcc

scripts/boot-services.sh starts the server, waits for it to bind, then starts the bot, waiting
for the VPN first - with TELEGRAM_LOCAL=1 a reboot that starts only the bot comes back degraded
or broken.
