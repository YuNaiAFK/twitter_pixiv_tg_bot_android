# v1.11 — 本機檔案製作 Telegraph

2026-11-09；版本 `1.11`、APK `versionCode=20`。

新增接收本機圖片、圖片文件與 ZIP／CBZ。傳完後輸入 `/publish`，以第一個檔案名稱（去掉副檔名）為標題，按檔名自然排序，將長邊最多 1280px 的 JPEG 預覽上傳 R2，再建立先標題、後圖片的 Telegraph。

完成訊息只讓「即時預覽」帶超連結，保留「作者」「E站」純文字。建議使用圖片文件或 ZIP／CBZ，以保留原始檔名；Telegram 照片沒有原始檔名，會使用訊息編號。GIF 預覽使用第一幀，原檔及既有 Pixiv GIF 文件傳送不變。

沿用 R2 內容去重、額度限制與失敗重試；只重試失敗圖片，三輪失敗後讓發起者選擇停止或再試。停止或有圖片未完成時不建立頁面。`/cancel_upload` 可取消；待製作資料依聊天及使用者隔離，重啟前請先發布。已建立頁面但回覆失敗時，重試會沿用頁面。

每批最多 512 MiB 輸入與 500 張圖片，單張最多 64 MiB／4000 萬像素，ZIP 圖片解壓合計最多 1 GiB。拒絕不安全路徑、符號連結、加密圖片與重複檔名。頁面超限會要求分批，不截斷圖片。支援 Windows Docker 與 Android Termux／proot 的本機 Bot API 檔案路徑。

新增 19 項離線測試；Windows 與 Android 原始碼各執行 91 項相關測試通過（其中 2 項環境條件略過）。Telegram、R2 與 Telegraph 皆使用替身，未向管理員傳送測試訊息或建立公開測試頁面。

已連線手機也通過 91 項測試（Windows Docker 案例略過），同步程式並重新啟動成功；管理 App 與面板均確認為 `1.11 / 20`。

APK 是管理介面；既有安裝也需要同步更新 Python 程式（包含新的 `bot/local_uploads.py`）並重新啟動 bot，僅安裝 APK 不會替換執行中的程式。
