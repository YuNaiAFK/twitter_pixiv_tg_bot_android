# v1.18 — 新增 7z 與 RAR 圖片壓縮檔

2026-11-09；版本 `1.18`、APK `versionCode=28`。

本機製作 Telegraph 新增 `.7z`、`.rar`，包含大寫副檔名。私聊附件與群組回覆檔案的 `/publish@機器人名稱` 入口同步辨識，沿用 ZIP／CBZ 的管理員限制、上傳確認、單則操作訊息、文字連結記憶、日期、1280px 圖片與 R2 去重流程。

透過 libarchive-c 與系統 libarchive 串流讀取圖片，不直接還原封存檔提供的路徑。沿用 500 張、單張 64 MiB、圖片解壓總量 1 GiB 限制，拒絕不安全路徑、連結項目與重複檔名。加密、毀損、不完整分卷或不支援的壓縮方式會在原操作訊息提示，尚未成功解壓前不開始上傳 R2。

Windows 新增 `libarchive-c>=5.3,<6` 依賴，優先使用系統 `System32/archiveint.dll`，也可用 `LIBARCHIVE` 指定系統 libarchive。Android 的安裝與引導腳本加入 `libarchive` 系統套件及 Python 介面；已連線手機已安裝 libarchive 3.8.11 與 libarchive-c 5.3。

新增四項真實封存檔測試，使用 7z 與自製 RAR4 store 圖片檔驗證解壓、Unicode 檔名、排序、路徑、重複檔名、大小與張數限制，以及毀損檔案錯誤；另新增附件副檔名辨識測試。Windows 127 項相關回歸測試通過（2 項環境條件略過），未建立公開測試頁面或傳送測試訊息。

手機 127 項相關測試也通過（Windows Docker 案例略過），已同步程式、依賴與說明並重新啟動；安裝腳本語法檢查通過，管理 App 與面板確認為 `1.18 / 28`。

既有安裝須同步程式（含新的 `bot/archive_images.py`）、安裝解壓依賴並重啟 bot；只安裝管理 APK 不會更新程式及依賴。
